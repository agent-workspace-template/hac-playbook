# Playbook に聞く（playbook-qa）

AI に任せていて出た疑問に、Playbook を参考にして答える。Playbook は正解集ではなく「今の AI との組み方」なので、該当する型があればそれを答えの軸にし、一般の知識で補ってよい。答えの中で、どこが Playbook の型で、どこが一般の知識かを分けて示す。型が今の道具や場面に合わないと考えるときは、そう言って理由を添える。Playbook とこの Skill は同じ配布 repo に入っていて、`~/.agents/skills/playbook-qa` はその clone 内の `playbook-qa/` へのリンク。clone の場所は問わない。書き換えない。

## 0. 更新の確認（毎回、答える前に）

```bash
bash ~/.agents/skills/playbook-qa/check-update.sh
```

- 出力の1行目と「版:」の行を、答えの冒頭にそのまま添える。`PLAYBOOK:` の行が本文の場所で、以降の `$P` はこれを使う。取り込みがあった場合は、この SKILL.md も更新されているので読み直す。
- `NG:` で止まったら、その出力を伝えて終了する（clone が無い・手元の変更がある・取り込めない）。
- `WARN:` は続行する。手元の版で答えたことを明記する。

## 1. 読むもの（全文は読まない。索引 → 該当項目の順）

Playbook は 900 行あるので、`section.sh` で必要な節だけ取り出す。他のファイルは読まない。`$P` は 0 の `PLAYBOOK:` 行のパス。

1. 型の番号が分からない質問は、まず「場面索引」だけを読む（約 40 行）。

```bash
bash ~/.agents/skills/playbook-qa/section.sh "$P" index
```

2. 索引で当たりを付けた型（例：B-5）の項目だけを読む（約 20 行）。複数なら繰り返す。

```bash
bash ~/.agents/skills/playbook-qa/section.sh "$P" B-5
```

- 「土台」「はじめに」など考え方そのものの質問だけ、その節を取り出す：`section.sh "$P" 土台`
- 索引に当たりが無ければ `section.sh "$P" list` で見出し一覧を見て探す。無ければ、型なしで答える。

## 2. 手順

1. 0 の確認結果を控える。
2. 1 で該当する型を探す。あれば、その型の要点を答えの軸にする。型の意味を言い換えて変えない。
3. 一般の知識で補ってよい。ただし、どこが型でどこが補いかを、読み手が区別できる書き方にする（文中に「（Playbook D-3）」と添える、または段落を分ける）。
4. 型が今の道具や場面に合わないと考えるときは、そう言って理由を添える。それは AI の見立てだと分かる書き方にする（例：「私の見立てでは」）。
5. 道具の操作（設定・コマンド・画面）を答えるときは、確かめ方（実行するコマンド、見る画面）を添える。版や環境で変わることは「変わりうる」と書く。断定できないことは断定しない。
6. 質問に含まれる仕事の事情は、答えの中で繰り返さない（G-1）。
7. 答えの型：
   - 1行目：更新の確認結果（0 の出力）
   - 結論
   - 根拠を1行：`参考：Playbook D-3`（複数可）。型を使わなかったときは `参考：Playbook に該当する型なし`
   - 要点を 2〜4 行。型の部分と補いの部分を区別する。Playbook の項目は全文を転記しない（本人が本文を読む前提）
   - 該当する型が無かったとき、または型が合わないと言ったときは、最後に「場面を添えて配布担当者に送ると次の版の材料になる」と1行添える

## 3. 書き込み先と書式

- 何も書き換えない（clone の fast-forward 取り込みだけは 0 のスクリプトが行う）。
- 外部送信（メール・投稿）はしない。

## 4. 完了時に伝えること

確認した版、参考にした型番号（または該当なし）、型が合わないと判断したものの有無。
